# Critical FAR Disclosure

**Evidence before claims. Preservation before presentation.**

This public repository is intended for carefully scoped documentation of security findings, vendor response or non-response, and subsequent remediation history. **Only material actually committed here should be treated as published evidence.**

## Current scope

The repository began as a minimal disclosure workspace. Refer to its tracked files, commits, and any published releases to see what evidence is currently available. A repository title or description is **not** proof of a vulnerability or a finding.

## Evidence standard

- Separate directly observed facts from hypotheses and interpretations.
- Identify affected versions, dates, reproduction conditions, and source revisions when they can be disclosed safely.
- Preserve original evidence, provenance, checksums, and a clear correction history where applicable.
- Record vendor communication and remediation status without implying a response that has not been documented.
- Do not publish private conversations, credentials, user data, tokens, or active exploit details.

## Responsible reporting

Do not submit unpatched sensitive vulnerabilities or private artifacts through public issues or pull requests. Use **Security → Report a vulnerability** for a private report; see [SECURITY.md](SECURITY.md) for reporting and evidence-handling guidance.

## Contributions

Read [AGENTS.md](AGENTS.md) before proposing changes. Contributions should be factual, limited to the relevant evidence, and independently reviewable.
